### 2. 🧪 Tests · 🟡 Minor · ⚡ Quick win
**The regenerated usecase test is never compiled or executed by this suite** — `test/commands/make_command_test.dart`

`writeExistingMockInfra()` writes the four stubs as plain `// FIXTURE-STUB …` comments (no Dart classes), and the PR body states the regenerated tests "are never executed by this suite, the assertions only check they were produced and reference the right field." So the test proves *a file was generated referencing `ChatMessageFields.content`*, not that the generated test is **valid/compilable**. If the generator ever regressed to emit broken content, this suite would stay green.

**Suggested hardening:** after generation, run `dart analyze` on the produced usecase test file (or at least assert the file parses), so the test also guards generation *quality*, not just presence. Also note: because the stubs contain no classes, any future generator change that makes the generated test `import`/use a symbol from them would break in a way this suite can't see.

regressions are caught, not just presence.
