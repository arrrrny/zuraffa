# x-ray — DTD/VM-Service element mapping + debug overlay

The `xray` plugin gives every UI element Zuraffa generates a **stable,
deterministic key** and renders a **debug overlay** on top of your app so
you (or an agent) can find and trigger elements without navigating the UI.

It solves two problems at once:

1. **DTD / VM Service element mapping** — every button the overlay renders
   carries a predictable `Key`, so a Device Test Driver (DTD) client or any
   `dart:developer` VM Service agent can locate and tap elements
   programmatically. No fragile `find.text()` or accessibility labels.
2. **X-Ray debug overlay** — in debug/profile builds, a dark, DevTools-style
   panel lists your app's UseCases (from the `api` bridge), Repositories,
   DataSources, Controllers, Presenters, Services, Routes (from the element
   registry) and a full endpoint catalog. Tapping a button fires the UseCase
   through the **existing `api` bridge** — x-ray never re-implements RPC.

## Quick start

```dart
void main() {
  WidgetsFlutterBinding.ensureInitialized();

  ZuraffaApiBridge.init();          // api plugin
  registerProductApiBridge();       // generated by `zfa api Product`

  // Optional: register non-UseCase elements + typed-form schemas.
  XRayPlugin().registerElement(
    type: XRayElementType.repository,
    domain: 'product',
    name: 'ProductRepository',
  );
  XRayPlugin().registerEntitySchema('Product', const [
    XRayEntityField(name: 'id', type: 'int'),
    XRayEntityField(name: 'name', type: 'String'),
  ]);

  Zuraffa.enableXRay(const XRayConfig(
    useCases: true,
    repositories: true,
    endpointCatalog: true,
  ));

  runApp(const XRayHost(child: MyApp())); // <- mounts the overlay
}
```

**Release builds**: `enableXRay` is a no-op when `kReleaseMode` is true —
leave the call in `main()` unconditionally.

**When disabled**, `XRayHost` returns your app widget directly: no overlay,
no keys, zero footprint in the widget tree.

## The deterministic key scheme

Format: `xray::<elementType>::<domain>::<name>` (domain omitted for
non-domain-scoped types).

| Key | Example |
|---|---|
| `XRayElementKey.useCase(domain, name)` | `xray::usecase::barcode_listing::scanBarcode` |
| `XRayElementKey.repository(domain, name)` | `xray::repository::product::ProductRepository` |
| `XRayElementKey.dataSource(domain, name)` | `xray::datasource::product::ProductRemoteDataSource` |
| `XRayElementKey.controller(name)` | `xray::controller::ProductController` |
| `XRayElementKey.presenter(domain, name)` | `xray::presenter::product::ProductPresenter` |
| `XRayElementKey.service(name)` | `xray::service::AuthService` |
| `XRayElementKey.route(name)` | `xray::route::/products` |
| `XRayElementKey.endpoint(method)` | `xray::endpoint::ext.zuraffa.product.getProduct` |
| Fixed | `xray::overlay::root`, `xray::overlay::close`, `xray::overlay::launcher` |
| Forms | `xray::form::submit::<method>`, `xray::form::field::<method>::<param>` |

A DTD agent can go straight to:

```dart
await driver.tap(find.byValueKey('xray::usecase::barcode_listing::scanBarcode'));
```

No UUIDs, no counters, no `hashCode` — keys are pure functions of the
domain + element names your generated code already knows.

## Behavior

| Scenario | Result |
|---|---|
| `useCases: true`, N endpoints registered | "UseCases" section with N buttons, keyed `xray::usecase::<domain>::<name>` |
| Tap a `NoParams` endpoint button | Invokes the api bridge handler in-process, shows the result in a snackbar |
| Tap an endpoint with params | Opens an inline form first (typed fields when an entity schema is registered, raw text fields otherwise) |
| `endpointCatalog: true` | "Catalog" section lists every endpoint with method, stream marker and return type |
| Section toggle `false` | The section does not render |
| Overlay dismissed | Close button or `Esc` collapses to a floating launcher; tap it to re-open. App state is preserved — the host never remounts your widget tree. |
| Release build | `enableXRay` is a no-op |

## How invocation works (no new RPC)

`ZuraffaApiBridge` keeps an in-process mirror of every handler it registers
with `dart:developer`. `XRayButton` calls
`ZuraffaApiBridge.invokeLocally(method, params)`, which runs the **exact
same function object** an external VM Service client would reach — same
JSON parameter deserialization, same UseCase invocation, same `Result`
serialization. Only the websocket transport is skipped. External DTD access
through `ext.zuraffa.<domain>.<usecase>` is unaffected.

## Known DTD behavior

`hot_restart` via DTD does **not** re-run `main()`. VM Service extensions
registered from the cold start persist; x-ray's in-memory state (element
registry, overlay visibility) resets. The api bridge endpoints survive the
restart, so the overlay repopulates from the live catalog on the next build.
