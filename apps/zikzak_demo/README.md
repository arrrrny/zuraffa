# ZikZak Demo — zfa-only mock/UI-UX clone

A **self-contained Flutter mock app** demonstrating that a ZikZak-class app can be
built from scratch using **only zfa commands** (`zfa setup` → `zfa entity create`
→ `zfa make` → `zfa build` → `zfa route create`). Every architecture file —
entities, repositories, datasources, usecases, presenters/controllers/state,
DI, mock data, routes, tests — is generated by the zuraffa v6 CLI. The only
hand-written file is `lib/main.dart` (the app shell glue, mirroring the
reference ZikZak repo which also hand-writes its `main.dart`).

Everything is mocked via generated mock datasources (`--with=mock`) — no
backend, camera, ML, or Firebase.

## Run it

```bash
cd apps/zikzak_demo
flutter pub get
flutter run          # iOS simulator / Android emulator / macOS
flutter test         # 312 generated usecase tests
```

Build a debug APK (for emulator install):

```bash
flutter build apk --debug
# adb install build/app/outputs/flutter-apk/app-debug.apk
```

## What's inside

- **53 entities + 10 enums** covering the reference's core domains: grocery
  (item/product/store/price comparison), user/auth, walkthrough, subscription,
  feedback, listings (url/text/barcode) + deals, chat (session/message/AI),
  alerts (price/notification), ZikZak score, price-check invoice, app config,
  dynamic forms, spark family (url/text/barcode), devices/customers.
- **Full zfa architecture per entity**: domain (entity + usecases +
  repository) → data (datasource + mock datasource + mock data + data repo) →
  presentation (view + controller + presenter + state) → DI (repositories +
  usecases) → tests.
- **57 route modules** aggregated by the generated `getAllRoutes()` in
  `lib/src/routing/index.dart`, wired into a GoRouter in `lib/main.dart`.
- **312 generated usecase tests — all passing.**

## Demo script (60 seconds)

1. **Splash** — app boots to the generated Splash screen (`/splash`).
2. **Browse a list** — open any entity list route (e.g. grocery products):
   generated list view renders mock data from the mock datasource.
3. **Open a detail** — tap through to a detail view backed by the same mock
   store.
4. **Routes** — `getAllRoutes()` exposes 57 route modules; navigate with the
   generated `RouterExtension` helpers (`goToXList()`, `goToXDetail(id)`).
5. **Tests** — `flutter test` runs the 312 generated usecase tests in seconds.

## Architecture map (generated)

```
lib/
├── main.dart                        # hand-written app shell (only file)
└── src/
    ├── domain/entities/…            # zfa entity create (Zorphy-first)
    ├── domain/usecases/…            # zfa make (per-method usecases)
    ├── domain/repositories/…        # zfa make (repository interfaces)
    ├── data/datasources/…           # zfa make (remote + mock datasources)
    ├── data/mock/…                  # zfa make --with=mock (mock data)
    ├── data/repositories/…          # zfa make (data repo implementations)
    ├── presentation/pages/…         # zfa make (view/controller/presenter/state)
    ├── di/…                         # zfa make (service locator + registrations)
    └── routing/…                    # zfa route create (routes + getAllRoutes)
```

## What to change

| Want to change | File |
| --- | --- |
| Mock data (prices, stores, items) | `lib/src/data/mock/*_mock_data.dart` |
| Mock latency / behavior | `lib/src/data/datasources/*/*_mock_datasource.dart` |
| A screen's layout | `lib/src/presentation/pages/<feature>/*_view.dart` |
| Route paths / names | `lib/src/routing/*_routes.dart` (regenerate via `zfa route create`) |
| Add an entity | `zfa entity create` + `zfa make <Entity> --preset=crud --with=vpc,state,di,test,mock` + `zfa build` |
| Add a screen (non-entity) | `zfa view custom --name <Name>` + `zfa route custom --name <Name>` |
| Theme | `lib/main.dart` (ShadTheme data) |

## Convention notes

- Generated by **zuraffa v6** (local `development` branch) via the canonical
  workflow: `zfa setup` → `zfa entity create` → `zfa make` → `zfa build` →
  `zfa route create`.
- Local path deps: `zuraffa_flutter`/`zuraffa`/`zorphy`/`zorphy_annotation`
  overridden to the dev checkouts (required for `autoId` support — zorphy ≥2.2.0).
- shadcn_ui `^0.56.1` surface (matching `grocery_scan_demo` convention).
- No `pumpAndSettle` needed in tests — generated usecase tests are pure Dart
  (no widgets), so they run fast and deterministically.
