# Feature Specification: Zuraffa Branding for Generated Apps

**Feature Branch**: `053-zuraffa-branding`

**Created**: 2026-09-01

**Status**: Draft

**Input**: User description: "To establish an outstanding branding and embracing the spirit of Zuraffa (Giraffe) I just created zuraffa_app_icons, all zfa generated apps using zfa setup both flutter and dart correctly should use zuraffa branding, completely repeal all the flutter icons."

## User Scenarios & Testing *(mandatory)*

### User Story 1 - Flutter Apps Use Zuraffa Branding (Priority: P1)

A developer runs `zfa setup` or `zfa make` to create a new Flutter application. The generated app automatically uses Zuraffa (giraffe) branded icons for all app icon surfaces — iOS App Store icon, iOS app icon, Android adaptive icon, and Play Store listing assets.

**Why this priority**: This is the primary brand showcase surface. All Flutter apps generated by zfa must immediately present the Zuraffa identity to end users.

**Independent Test**: Can be tested by running `zfa setup` or `zfa make` for a Flutter app and verifying that all icon files under `assets/` and platform-specific icon directories contain giraffe branding, not default Flutter logos.

**Acceptance Scenarios**:

1. **Given** a Flutter project generated by `zfa setup`, **When** the developer inspects `assets/` and `android/app/src/main/res/`, **Then** all icon files reference giraffe/Zuraffa imagery, not Flutter logo.
2. **Given** a Flutter project generated by `zfa make`, **When** the developer builds for iOS, **Then** the app bundle contains Zuraffa-branded icons in all required sizes.
3. **Given** an existing Flutter project running `zfa setup`, **When** the command completes, **Then** all Flutter default icons are replaced with Zuraffa branding.

---

### User Story 2 - Dart CLI Apps Use Zuraffa Branding (Priority: P1)

A developer runs `zfa setup` or `zfa make` to create a new Dart CLI application. The generated app includes Zuraffa brand assets in its `assets/` directory, and the README references the giraffe mascot appropriately.

**Why this priority**: Dart CLI tools need consistent Zuraffa identity to reinforce brand recognition across the entire Zuraffa ecosystem.

**Independent Test**: Can be tested by running `zfa setup` or `zfa make` for a Dart CLI app and verifying that `assets/` contains giraffe logos and the project README includes Zuraffa branding.

**Acceptance Scenarios**:

1. **Given** a Dart CLI project generated by `zfa setup`, **When** the developer checks the `assets/` directory, **Then** it contains Zuraffa brand assets (logo, mascot).
2. **Given** a Dart CLI project generated by `zfa make`, **When** the developer opens the README, **Then** it references Zuraffa/ZikZak with appropriate branding.

---

### User Story 3 - No Flutter Default Icons Remain (Priority: P2)

All traces of Flutter's default logo/icons are removed from generated apps. The generated code references only Zuraffa assets.

**Why this priority**: Complete brand replacement is essential for professional Zuraffa identity. Partial replacement (leaving Flutter default icons) would undermine the branding effort.

**Independent Test**: Can be tested by running a search across the generated project for any Flutter logo references or default Flutter icon file names.

**Acceptance Scenarios**:

1. **Given** a Flutter project generated by `zfa setup`, **When** searching for "flutter" in asset references and "Icon" in drawable resources, **Then** no results contain default Flutter logos or icon filenames.
2. **Given** a Dart CLI project generated by `zfa setup`, **When** searching for "dart" logo references in README and assets, **Then** no default Dart logo references remain.

---

### Edge Cases

- Generated apps that already have custom icons should be warned but allow override
- Apps with missing or incomplete asset directories should be handled gracefully
- Zuraffa brand assets must exist at a known, stable path before generation

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: `zfa setup` and `zfa make` for Flutter apps MUST copy Zuraffa app icon assets to the generated project's `assets/` directory
- **FR-002**: Flutter app icon configuration files (Android `ic_launcher`, iOS `Assets.xcassets/AppIcon.appiconset`) MUST reference Zuraffa giraffe imagery
- **FR-003**: Dart CLI apps generated by `zfa setup` and `zfa make` MUST include Zuraffa brand assets in their `assets/` directory
- **FR-004**: All generated apps' README files MUST include Zuraffa branding with reference to the giraffe mascot/ZikZak
- **FR-005**: Default Flutter logo icons (FlutterLogo, `flutter.png`, `flutter_animated.png`) MUST be absent from generated Flutter apps
- **FR-006**: The branding system MUST use a configurable asset source path (default: `assets/zuraffa_app_icons/`)
- **FR-007**: Generated apps MUST NOT reference any default Flutter/Dart logos in code or assets

### Key Entities

- **BrandAsset**: Zuraffa giraffe icon files in multiple resolutions/formats for app icons and marketing assets
- **GeneratedApp**: A Flutter or Dart project created by `zfa setup` or `zfa make` with brand configuration
- **BrandConfig**: Configuration specifying asset source path and brand metadata for generated apps

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 100% of newly generated Flutter apps have Zuraffa app icons (verified by asset file hash comparison)
- **SC-002**: 100% of newly generated Dart CLI apps have Zuraffa brand assets in `assets/` directory
- **SC-003**: Zero generated Flutter apps contain any file named `flutter.png`, `flutter_animated.png`, or references to `FlutterLogo` in configuration
- **SC-004**: All generated app READMEs contain Zuraffa branding within the first 10 lines

## Assumptions

- Zuraffa brand assets exist at `assets/zuraffa_app_icons/` with iOS, Android, and asset store ready images
- Generated apps follow standard Flutter project structure for icon placement
- The `zfa setup` and `zfa make` commands have plugin/template infrastructure that can be extended for branding
- Brand assets include multiple icon sizes required by iOS App Store (1024x1024), iOS devices (180x180, 120x120, etc.), and Android adaptive icons
