# Feature Spec: Contract Lane Hardcodes package:test and Relative Subject Import [SPEC 1513]

**Feature ID:** 1513-contract-lane-flutter-imports
**Issue:** #1513
**Related:** #1351 (unit/acceptance lanes already honor flutterTest), #1035 (package subject import, one source of truth), #1007 (contract lane)
**Status:** IN_PROGRESS

## Summary

On a Flutter host, every contract-kind behavior generated by `zfa tdd gen` is
dead on arrival: the contract test imports plain `package:test` (unresolvable
under the flutter_test runner) and reaches the paired seam through a legacy
relative path (lint-hostile per #1035). `zfa tdd run 001-todo-app` on Flutter
stops at the very first contract behavior — `contract:A1 verify-red` fails
with `Couldn't resolve the package 'test'` before a single contract case is
graded. The unit and acceptance lanes fixed both defects in #1351/#1035; the
contract lane never received the same treatment.

## Problem

```bash
flutter test test/tdd/001-todo-app/contract_a1_test.dart
# Error: Couldn't resolve the package 'test'
```

Unit/acceptance lanes import `package:flutter_test/flutter_test.dart` (#1351)
and compile fine. Every contract test imports unresolvable plain
`package:test`. The subject import uses relative `../../../lib/tdd/...` where
unit/acceptance use `package:<name>/tdd/...`.

Root cause (`contract_test_writer.dart`):

1. Both templates (parseable `_render` and unparseable `_renderUnparseable`)
   hardcode `import 'package:test/test.dart';`. `ContractTestWriter` has no
   `flutterTest` field.
2. `_relativeSubjectPath` only computes the legacy relative shape — it never
   consults the `package:` import rule the unit lane uses (#1035).
3. `gen_command.dart` `_writersFor` constructs `const ContractTestWriter()`
   WITHOUT passing the already-resolved `flutterTest` flag.

## Requirements

### FR-1 — ContractTestWriter honors the host runner

`ContractTestWriter` gains a `flutterTest` field defaulting to `false` plus a
`_testImport` getter mirroring `BehaviorTestWriter._testImport`: when
`flutterTest` is true the templates import
`package:flutter_test/flutter_test.dart`, otherwise `package:test/test.dart`.

### FR-2 — One source of truth for the package subject import

`BehaviorTestWriter._packageSubjectImport` is promoted to a public static
`packageSubjectImportFor(String testPath, String subjectPath)` so both lanes
answer the question identically. The contract lane's subject import becomes
`package:<name>/<path-under-lib>` when the subject sits under the enclosing
project's `lib/` (pubspec resolvable), with the legacy relative path kept as
the fallback (non-absolute fixture paths, no pubspec, subject outside `lib/`).

### FR-3 — gen threads the flag into the contract pair

`_writersFor` passes the resolved `flutterTest` flag into
`ContractTestWriter` for contract-kind behaviors. The stale-stub re-render
path (`_regenerateStaleStub`) inherits the fix — it already threads the flag
into `_writersFor`.

### FR-4 — The unparseable template honors the flag too

The refusal-shaped unparseable contract test imports the same `_testImport`
surface (no second-class hardcode left behind).

### FR-5 — Pure-Dart default is byte-stable

With `flutterTest: false` (the default), a contract pair generated for a
subject that does NOT resolve a package import (no pubspec, or subject
outside `lib/`) renders byte-for-byte what today's binary renders.

## Hard Constraints

- Fix ONLY contract lane imports in `contract_test_writer.dart` and
  `gen_command.dart`.
- Do NOT change unit lane, acceptance lane, state machine, or loop semantics.
- Pure-Dart output must remain byte-stable (FR-5 shape).
- Related: #1351, #1035.

## Measurable Success Criteria

1. `ContractTestWriter` gains `flutterTest` field (default `false`) and a
   `_testImport` getter; with `flutterTest: true` the parseable template
   emits `import 'package:flutter_test/flutter_test.dart';` and never
   `import 'package:test/test.dart';`. **[SC-1]**
2. `BehaviorTestWriter._packageSubjectImport` is reachable as public static
   `packageSubjectImportFor` and answers identically for the contract lane. **[SC-2]**
3. `_writersFor` threads `flutterTest` into `ContractTestWriter`; a
   `zfa tdd gen contract:A1` on a fixture whose pubspec declares a `flutter:`
   dependency produces a contract test importing `flutter_test`. **[SC-3]**
4. The unparseable template honors `flutterTest` the same way. **[SC-4]**
5. Pure-Dart default unchanged: default writer output for the no-pubspec
   fixture shape is byte-identical to the pre-fix render. **[SC-5]**
6. Regression coverage: flutter_test on Flutter; default stays `package:test`;
   package subject import under `lib/`; relative fallback outside `lib/`. **[SC-6]**

## Out of Scope

- `ContractSubjectWriter` output (the seam never imports the test framework).
- Unit/acceptance/ffi/persistence/platform/theme lanes (already correct).
- The run driver, red classifier, and state machine.
