# Data Model: `zfa tdd corpus` — batch driving, provenance audit, gap ledger

## Entities

### CorpusFeatureProgress (value object — new)

Per-feature corpus state, persisted in `progress.json`.

- `name` (String) — feature directory name, e.g. `001-app-bootstrap`
- `state` (CorpusFeatureState) — pending / driving / done / stopped / waived / not-ready / dropped
- `gateOutcome` (String?) — verify gate result: `PASS`, `FAIL_SURVIVED`, `FAIL_TIMEOUT`, `PREFLIGHT_RED`, `NOT_ASSESSED`, or `null` (not yet gated)
- `waived` (WaiverRecord?) — explicit waiver when gate is not PASS

### CorpusFeatureState (enum — new)

| Value | Meaning |
|-------|---------|
| `pending` | not yet started |
| `driving` | `zfa tdd run` in progress |
| `done` | run complete + verify gate passed (or waived) |
| `stopped` | run or gate failed; gap ledger entry exists |
| `waived` | verify gate waived with recorded reason |
| `not-ready` | skipped per manifest (not loop-ready) |
| `dropped` | removed from manifest after being driven (audit trail) |

### WaiverRecord (value object — new)

- `reason` (String) — why the gate was waived
- `actor` (String) — who waived it (e.g. "maintainer" or agent id)
- `when` (String) — ISO-8601 UTC timestamp

### GapLedgerEntry (value object — new)

Append-only stop record in `gap-ledger.json`.

- `feature` (String) — feature directory name
- `behavior` (String?) — behavior id if stopped during loop driving
- `step` (String?) — step that failed (gen/verify-red/make/refactor/verify)
- `outcome` (String) — stop outcome (stopped/runner-error/FAIL_SURVIVED/etc.)
- `command` (String) — the failing command string
- `issueLink` (String?) — GitHub issue URL (populated when filed)
- `timestamp` (String) — ISO-8601 UTC when the stop occurred
- `resolution` (String?) — null while blocking; set to "resolved" when a later run passes

### ProvenanceRecord (value object — new)

File→invocation mapping in `provenance.json`.

- `filePath` (String) — relative path under `lib/`, e.g. `lib/src/domain/entities/product/product.dart`
- `source` (ProvenanceSource) — `cycle-log` / `setup` / `import` / `carve-out`
- `invocation` (String) — the zfa command that produced the file (e.g. `zfa make Product --preset=crud`)
- `feature` (String?) — feature name when attributed to a cycle log
- `timestamp` (String?) — ISO-8601 UTC from the cycle log entry

### ProvenanceSource (enum — new)

| Value | Meaning |
|-------|---------|
| `cycle-log` | generated by a `zfa make` / `zfa build` in the TDD loop |
| `setup` | scaffold file from `zfa setup` |
| `import` | copied during corpus import |
| `carve-out` | declared manual-UI exemption |

### CarveOutEntry (value object — new)

Entry in the versioned `carve-out.json` manifest.

- `path` (String) — relative path under `lib/`
- `reason` (String) — why this file is manually written
- `addedBy` (String) — who added the entry
- `addedAt` (String) — ISO-8601 UTC

### CorpusProgress (model — new)

Aggregate corpus state, persisted at `.zfa/corpus/progress.json`.

- `features` (Map<String, CorpusFeatureProgress>) — per-feature state
- `inFlight` (bool) — corpus-level concurrency guard
- `ownerPid` (int?) — pid of the driving process
- `startedAt` (String?) — ISO-8601 UTC when the current run started
- `lastUpdatedAt` (String?) — ISO-8601 UTC of last state change

## Invariants

- Gap ledger is append-only: entries are never edited; resolution is a
  new entry with the same feature name.
- Corpus progress is atomically written via temp+rename (same pattern
  as `RunStateStore`).
- A feature is `done` ONLY when its verify gate passes or a waiver is
  recorded; `NOT_ASSESSED` and every failure stop the run.
- Provenance audit attributes 100% of `lib/` files; any unattributed
  file fails the audit by name.
- Concurrent corpus runs are refused via the in-flight marker.

## State Transitions

Per feature across corpus runs:

```text
pending       --corpus run starts--> driving
driving       --run+verify pass--> done
driving       --run stops--> stopped (+ ledger entry)
driving       --verify NOT_ASSESSED--> stopped (+ ledger entry)
driving       --verify waived--> waived (+ waiver record)
not-ready     --skipped--> not-ready (unchanged)
done          --removed from manifest--> dropped (audit trail)
stopped       --re-run, feature passes--> done (+ resolution ledger entry)
```

## File Contracts

- Progress: `<app>/.zfa/corpus/progress.json`
- Gap ledger: `<app>/.zfa/corpus/gap-ledger.json`
- Provenance: `<app>/.zfa/corpus/provenance.json`
- Carve-outs: `<app>/.zfa/corpus/carve-out.json`
- Manifest (from #627): `<app>/.zfa/manifests/corpus-manifest.json` (read-only)
