## Round 2 — GREEN

Implementation (all five orders):

- `lib/src/plugins/datasource/datasource_verifier.dart` (new): AST gate —
  entity parse/fields, interface method signatures, `UpdateParams`/
  `DeleteParams`/`ToggleParams` first-type-argument conformance vs the
  entity's declared id-field type, entity-type reference conformance for
  standard CRUD methods; parse errors become findings, never throws.
- `lib/src/commands/datasource_verify_command.dart` (new): thin CLI —
  exit 0/1/2 + `--> fix:` lines; `--json` → `VerdictEnvelope` (verdict.v1).
- `lib/src/plugins/datasource/datasource_receipt.dart` (new):
  `DatasourceReceiptWriter` — deterministic `datasource-<entity>.json`
  receipt via `ReceiptStore.saveNamed`, extras `interface_sha256` +
  `entity_source` (path + sha256 + bytes).
- `lib/src/plugins/datasource/capabilities/create_datasource_capability.dart`:
  `projectRoot` injectable; FULL execute()/plan() try/catch; explain
  short-circuit (read-only); receipt persisted by the capability on
  successful non-dry-run generation.
- `lib/src/plugins/datasource/datasource_explain.dart` (new):
  `DatasourceExplainer` — types (remote/local/mock/sqlite), entity
  field→method mapping, interface shape signatures.
- `lib/src/commands/datasource_command.dart`: verify subcommand registered;
  `--explain` parent flag (+ consumedParentFlags); `_emitReceipt` rerouted
  through the shared writer (same document shape on both paths).
- `lib/src/commands/capability_command.dart`: prints `data['explain']`
  (generic, read-only path).
- `lib/src/plugins/datasource/builders/{interface,remote,local}_generator.dart`:
  fresh emissions stamped with `DatasourceProvenance.headerFor(...)`;
  append/merge paths untouched (header preserved by the AST engine).
