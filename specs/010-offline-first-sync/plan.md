# Implementation Plan: Offline-First Sync Plugin

**Branch**: `010-offline-first-sync` | **Date**: 2026-06-28 | **Spec**: [spec.md](./spec.md)

**Input**: Feature specification from `/specs/010-offline-first-sync/spec.md`

## Summary

The sync plugin adds true offline-first (local-first) architecture to Zuraffa's code generation. It is the inverse of the existing cache plugin: where cache treats remote as the source of truth and local as a temporary cache, sync treats **local as the source of truth** with background synchronization to remote. The plugin generates a `SyncStrategy` (injected into the repository, analogous to `CachePolicy`), a separate `SyncMetadataStore` (Hive box tracking per-record sync status without polluting the domain entity), and a `Sync<Entity>UseCase` for manual triggering. The sync-enabled repository writes to local first (instant, offline-capable), reads from local only, and delegates push/pull orchestration to the injected `SyncStrategy`.

## Technical Context

**Language/Version**: Dart ^3.11.0

**Primary Dependencies**: code_builder (AST generation), hive_ce (local storage), zuraffa core (Clean Architecture base classes, UseCase, Result, CancelToken, GetIt)

**Storage**: Hive CE (local-first persistence), separate Hive box for sync metadata

**Testing**: flutter test, mocktail (mocking), existing Zuraffa test patterns

**Target Platform**: Cross-platform Flutter (iOS 16.4+, Android, macOS, Web)

**Project Type**: Code generation framework (CLI tool + runtime library)

**Performance Goals**: Local writes <5ms, local reads <5ms, sync push <2s for <100 records

**Constraints**: Generated code must follow Clean Architecture rigidly (SOLID, DRY). Domain entity must stay pure (no sync infrastructure fields). Must be compatible with existing `--cache` plugin.

**Scale/Scope**: Plugin affects: `lib/src/plugins/sync/` (new), `lib/src/core/` (SyncStrategy interface), `lib/src/plugins/repository/` (sync-aware repository generator), `lib/src/plugins/di/` (sync DI registration), `lib/src/cli/plugin_loader.dart` (register plugin), `lib/zuraffa.dart` (export new types).

**Structure Decision**: The `SyncPlugin` lives in `lib/src/plugins/sync/` following the exact same directory structure as `lib/src/plugins/cache/`. The core interfaces (`SyncStrategy`, `SyncStatus`, `SyncMetadata`) live in `lib/src/core/` alongside `CachePolicy`, and are exported via `lib/zuraffa.dart`. The repository generator gains a new synced-method extension (`implementation_generator_synced.dart`) that mirrors `implementation_generator_cached.dart`.
