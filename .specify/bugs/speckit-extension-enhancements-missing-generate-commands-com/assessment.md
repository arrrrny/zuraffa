## Description

The spec for feature `005-speckit-extension-enhancements` requires three commands:
1. `speckit.zuraffa.init` - **IMPLEMENTED** (as `zfa init` / `zfa initialize`)
2. `speckit.zuraffa.generate-commands` - **NOT IMPLEMENTED**
3. `extension.yml` manifest - **EXISTS** but lacks validation

The `generate-commands` command (FR-005 through FR-010, SC-002, SC-005) is completely missing from the codebase.

---

## Expected Behavior (from spec.md)

### FR-005: Parse `zfa manifest` JSON output
The command MUST run `zfa manifest` and parse the JSON output containing plugin capabilities.

### FR-006: Create .md files per plugin command
For each plugin capability, generate a `.md` file with:
- YAML frontmatter (name, description, category)
- Usage section
- When to Use guidance
- Required Parameters list
- Flags table (type, required, default, description)
- Example commands

### FR-007: Organize by category subdirectories
Files must be organized into:
- `commands/data/` - repository, datasource commands
- `commands/domain/` - usecase, service, provider commands
- `commands/presentation/` - view, controller, presenter, state, route commands
- `commands/scaffolding/` - feature scaffold commands
- `commands/testing/` - test, mock commands
- `commands/utilities/` - di, cache, config commands

### FR-008: Create command_registry.json
Machine-readable mapping of plugin commands to extension files.

### FR-010: Support --dry-run
Preview changes without writing files.

### SC-002: Exactly one .md file per plugin command
Output must match `zfa manifest` capability count.

### SC-005: Consistent frontmatter structure
All generated files follow the same format.

---

## Actual Behavior

Running `zfa generate-commands` produces:
```
❌ Unknown command: generate-commands
```

No such command exists in the CLI.

---

## Root Cause Analysis

### Missing Files
1. **`lib/src/commands/generate_commands_command.dart`** - Does not exist
2. **Command registration in `lib/src/cli/cli_runner.dart`** - Not added
3. **Tests** - No test file exists

### Related Existing Code
- `ManifestCommand` (`lib/src/commands/manifest_command.dart`) - Already outputs plugin capabilities as JSON
- `PluginLoader` (`lib/src/cli/plugin_loader.dart`) - Lists plugins with capabilities
- Extension structure at `.specify/extensions/zuraffa/commands/` - Target directory exists
- `extension.yml` - Already lists all 43 commands with aliases and categories

### Why This Happened
The spec was created (commit 12fd296, 2026-04-26) but the implementation was never completed. The `init` command was implemented earlier (as part of issue #275/#393), but `generate-commands` was left as a future enhancement.

---

## Impact Assessment

### User Impact
- **P1 User Story 2 blocked**: "When zfa CLI adds new plugin commands or changes flag schemas, the extension commands can be regenerated by running a single command"
- Developers must manually create/update 40+ command `.md` files when zfa changes
- No automated way to keep extension in sync with CLI

### Technical Debt
- Extension commands drift from actual CLI capabilities
- Manual maintenance burden for 43+ command files
- No single source of truth for command definitions

---

## Suggested Fix

### Implementation Plan

1. **Create `lib/src/commands/generate_commands_command.dart`**
   - Extend `Command<void>`
   - Accept `--output` and `--dry-run` flags
   - Use `ManifestCommand` logic or `PluginLoader` to get capabilities
   - Generate `.md` files using template matching existing format
   - Create `command_registry.json`

2. **Register in `cli_runner.dart`**
   - Add import
   - Add `_runner.addCommand(GenerateCommandsCommand())`

3. **Create Tests**
   - `test/commands/generate_commands_test.dart`
   - Test dry-run mode
   - Test output structure
   - Test idempotency

### Code Structure Suggestion

```dart
// lib/src/commands/generate_commands_command.dart
class GenerateCommandsCommand extends Command<void> {
  @override
  String get name => 'generate-commands';
  
  @override
  String get description => 'Regenerate speckit extension commands from zfa manifest';
  
  GenerateCommandsCommand() {
    argParser.addOption('output', abbr: 'o', 
        defaultsTo: '.specify/extensions/zuraffa/commands/',
        help: 'Output directory for generated .md files');
    argParser.addFlag('dry-run', negatable: false,
        help: 'Preview without writing files');
    argParser.addFlag('verbose', abbr: 'v', negatable: false);
  }
  
  @override
  Future<void> run() async {
    // 1. Get capabilities via PluginLoader or ManifestCommand
    // 2. For each capability, generate .md file
    // 3. Write to categorized subdirectories
    // 4. Generate command_registry.json
  }
}
```

### Reuse Existing Patterns
- Follow `ManifestCommand` pattern for getting plugin capabilities
- Follow `ManifestWriter` pattern for idempotent file writing
- Use existing frontmatter format from `.specify/extensions/zuraffa/commands/data/repository.md`
