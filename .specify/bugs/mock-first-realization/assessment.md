## Report (verbatim or summarized)

> EPIC: Mock-First Realization — the lifecycle where every behavior goes PENDING → RED → MOCKED → REAL → DONE. Supersedes #848 (stub-first TDD-120 epic). The plan of record shaped by live validation across a 5-feature build and a full audit of every past issue. "100% TDD-built" = every line of the app is either generated by zfa or a gate-proven hand-delta — never anything else.
>
> Workstreams: P0 — make-default→mock + mocked tier (#909), Spec-parser hardening (#919), Generator/runtime version-skew contract (#911), Template self-hosting (#912). P1 — `zfa tdd realize` (swap + gates + receipts), Simulation-mode DI binding, Differential harness (#915). P2 — Corpus economics, Treaty + error API unification (#917), CI referee.
>
> Definition of Done: (1) `zfa tdd corpus` drives all 120 ZikZak specs to `complete(mocked)` with zero hand-edits, (2) Realization ladder exercised on ≥10 adapter families to `complete(real)`, (3) Provenance SBOM per feature, (4) CI referee returns corpus verdict on every PR, (5) Rebuilt zik_zak publishes from this pipeline.

## Symptom

This is a tracking epic, not a single behavioral bug. The "symptom" is the collection of gaps in the current TDD lifecycle that prevent the MOCKED tier from being the default, prevent generated code from compiling against published zuraffa, and prevent the realization ladder from being exercised end-to-end. Each sub-issue (#909, #911, #912, #915, #917, #919) documents a specific symptom.

## Reproduction

1. Run `zfa tdd make <id>` — the default path generates a func-stub (`subject() => 0`) instead of a contract-conforming mock via `zfa mock create`. State stays at GREEN, never reaches MOCKED.
2. Create a fresh project consuming zuraffa from pub.dev (not path override), then generate persistence-kind behaviors — the generated test imports `package:zuraffa/zuraffa.dart` and references `PersistenceTestHarness`/`TestClock` which only exist on master, not in the published package.
3. Run `zfa tdd plan` on a spec authored with the zuraffa-1.0 template — the Key Entities table, Dependencies table, and Layer Contracts sections are invisible to the parser.
4. Attempt a realization (mock→real swap) — no fixture parity checker exists; the mock and real adapters may return different shapes without detection.
5. Run `zfa manifest --verify` — no such flag exists; the manifest does not self-validate against CLI flags.
6. Run `zfa tdd corpus` on all 120 specs — the pipeline stalls at behaviors that need mocked adapters but route through func-stubs instead.

## Suspected Code Paths

- `lib/src/plugins/tdd/services/generation_planner.dart` — the planner that maps behavior descriptions to `zfa tdd func` / `zfa make` / `zfa entity create` steps; currently has no path to `zfa mock create` (issue #909)
- `lib/src/plugins/tdd/commands/make_command.dart:1-100` — the make command that orchestrates generation steps; does not invoke mock-create as default
- `lib/src/plugins/tdd/models/behavior.dart:30` — `BehaviorState` enum: `{ pending, red, green, done }` — no `mocked` tier exists
- `lib/src/plugins/tdd/services/run_state_store.dart` — run-state persistence that would need to support the MOCKED tier
- `lib/src/testing/persistence_test_harness.dart` — `PersistenceTestHarness` and `TestClock` live here, in zuraffa source; the generated templates import them from `package:zuraffa/zuraffa.dart` but they may not be in the published package's barrel export
- `lib/src/plugins/tdd/services/spec_parser.dart` — parses spec.md; entity table support for zuraffa-1.0 tables exists partially but may need completing
- `lib/src/plugins/tdd/services/differential_ref_runner.dart` — the differential runner for generator ref testing; fixture parity between mock/real is not yet implemented
- `lib/src/commands/manifest_command.dart` — no `--verify` flag; manifest only outputs JSON

## Root Cause Hypothesis

**High confidence.** This is a deliberately-scoped epic where multiple P0/P1/P2 workstreams were identified through a 5-feature build audit. The current TDD lifecycle was designed around func-stubs (issue #829/#830 era), and the MOCKED tier is a new requirement that touches the behavior state machine, the generation planner, the make command, and the run driver. No single root cause — the gaps are orthogonal but interconnected. The sub-issues (#909, #911, #912, #915, #917, #919) each document their own local root cause.

## Proposed Remediation

**Preferred**: Tackle the P0 workstreams in dependency order:
1. **#909 (make-default→mock)** first — routes the make default through `zfa mock create`, adds MOCKED to `BehaviorState`, demotes func-stub to `--stub`. This unblocks the whole ladder.
2. **#911 (version-skew contract)** — gates generated imports against the published zuraffa API surface; adds `zfa doctor` import-resolution check.
3. **#912 (template self-hosting)** — fixes apostrophe escaping, widget template, migrate-paths, route dry-run defects.
4. **#919 (template structures)** — enhances spec parser to consume zuraffa-1.0 table formats.

Then P1 workstreams (#915 differential harness, realization ladder) and P2 (#917 treaty/error API, corpus economics).

**Alternatives**:
- Implement in parallel with sub-teams per workstream — faster but risks integration conflicts between #909 (state machine changes) and #917 (exit protocol changes).
- Implement #919 before #909 — allows the template structures to drive mock-first make, but delays the mocked tier.

**Files likely to change**:
- `lib/src/plugins/tdd/models/behavior.dart` — add `mocked` to `BehaviorState`
- `lib/src/plugins/tdd/services/generation_planner.dart` — add mock-create path
- `lib/src/plugins/tdd/commands/make_command.dart` — route through mock-create
- `lib/src/plugins/tdd/commands/run_command.dart` — support MOCKED tier in run loop
- `lib/src/plugins/tdd/services/run_state_store.dart` — persist MOCKED state
- `lib/src/commands/manifest_command.dart` — add `--verify`
- `lib/src/plugins/tdd/services/spec_parser.dart` — complete table parsing
- `lib/src/testing/persistence_test_harness.dart` — verify barrel export for published package

**Tests to add or update**:
- End-to-end test: `zfa tdd make` produces MOCKED state (not just GREEN)
- Version-skew test: generated code compiles against published zuraffa constraint
- Template structures test: `zfa tdd plan` parses Key Entities table (already exists at `test/plugins/tdd/bug_919_template_structures_test.dart`)
- Manifest verify test: `zfa manifest --verify` catches drift
- Differential fixture parity test: mock vs real adapter shapes match

## Risks & Considerations

- **Blast radius**: The MOCKED tier change touches the core state machine shared by `run`, `verify`, `doctor`, and `reset` commands — every consumer of `BehaviorState` must handle the new value.
- **Backward compatibility**: Existing run-state.json files with `{ pending, red, green, done }` must deserialize correctly with the new `mocked` value. `BehaviorState.values.byName()` (used in `RunState.fromJson`) would break if serialized states are on disk without the enum value — need migration or guard.
- **Pub.dev publishing**: #911 requires that harness/simulation APIs land in a published zuraffa release BEFORE or WITH the generator that emits them — this is a release coordination risk.
- **120-spec feasibility**: The corpus economics workstream (P2) must prove the full ladder runs in minutes, not hours, before the DoD is met.
- **No constitution file found**: `.specify/constitution.md` does not exist; this epic should not be gated on constitution principles.
