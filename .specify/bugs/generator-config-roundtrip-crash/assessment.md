# Bug Assessment: GeneratorConfig.toJson → fromJson round-trip always throws

- **Slug**: generator-config-roundtrip-crash
- **Created**: 2026-10-20
- **Source**: https://github.com/arrrrny/zuraffa/issues/1962 (allowlisted host: github.com)
- **Verdict**: valid
- **Severity**: high

## Report (verbatim or summarized)

Issue #1962 (author arrrrny, label `bug`): every full
`GeneratorConfig.toJson() → GeneratorConfig.fromJson(...)` round-trip throws
`type 'bool' is not a subtype of type 'String?'` at
`generator_config.dart` `new GeneratorConfig.fromJson`. Discovered on PR
#1961's branch `fix/issue-1952` by a new `overwrite_interface` JSON
round-trip test, which currently works around this pre-existing crash by
testing the two directions separately (workaround comment links to #1962).

## Symptom

`GeneratorConfig.fromJson(config.toJson(), name)` throws a runtime
`TypeError` for ANY config; the config can never be reconstructed from its
own JSON serialization.

## Reproduction

1. Build a plain config: `GeneratorConfig(name: 'Deal', outputDir: 'lib/src', methods: ['get'], generateMock: true)`.
2. Call `config.toJson()`.
3. Call `GeneratorConfig.fromJson(map, 'Deal')` → throws
   `type 'bool' is not a subtype of type 'String?'`.

Reproduced as the regression test
`test/fixes/bug_1962_config_json_roundtrip_test.dart` (fails RED on the
unfixed tree, passes GREEN after the fix).

## Suspected Code Paths

- `lib/src/models/generator_config.dart:309` —
  `customPresenterName: json['presenter'] ?? json['custom_presenter_name']`:
  `toJson` emits `'presenter': generatePresenter` (line 733, bool, always
  non-null), so the `??` fallback never engages and the bool lands in the
  `String?` field → runtime TypeError.
- `lib/src/models/generator_config.dart:310-311` — same overload for
  `customControllerName` with the `'controller'` key (emitted line 734).
- `lib/src/models/generator_config.dart:257-258` — the bool reads of the
  same keys (`json['presenter'] == true`) are correct and stay.
- `lib/src/models/generator_config.dart:312` — `state` NOT affected:
  `customStateName` reads `state_class` / `custom_state_name`, never the
  `state` bool key (line 739).

## Root Cause Hypothesis

The `presenter` / `controller` JSON keys are overloaded with two different
types on the two sides of the serialization surface: bool flags on write
(`toJson`), and both a bool flag AND a String? custom name on read
(`fromJson`). Because the bool is always non-null, the `??`
dedicated-key fallback is dead code and the bool is assigned into a
`String?` field, which is a runtime type error in every round-trip.
Confidence: high (confirmed by reading the source; crash reproduced).

## Proposed Remediation

**Preferred**: stop reusing the bool keys for the custom names — in
`fromJson` read only the dedicated keys:

```dart
customPresenterName: json['custom_presenter_name'],
customControllerName: json['custom_controller_name'],
```

`fromJson` is the replay path and `toJson` never emitted a String under
`presenter`/`controller`, so no producer loses data. Verified: the only
other `'presenter':` producers in `lib/` are `zfa_config.dart:31`
(`'presenter': true`, a bool flag template — handled by the `== true`
reads) and `generate_commands_command.dart:26` (an unrelated command→layer
map, not a GeneratorConfig payload).

**Alternatives**:
- Emit different keys from `toJson` (e.g. `generate_presenter`) — larger
  blast radius: changes the serialization surface every existing consumer
  reads. Rejected; the issue asks for the read-side fix.

**Files likely to change**:
- `lib/src/models/generator_config.dart` (2 lines)
- `test/fixes/bug_1962_config_json_roundtrip_test.dart` (new)

**Tests to add or update**:
- Round-trip `fromJson(toJson())` on a plain CRUD config (the crash).
- Round-trip with custom presenter/controller names (the dedicated keys).
- Round-trip with `generatePresenter`/`generateController` true (the bools).

## Risks & Considerations

- A hand-written JSON payload that stored a custom name under
  `'presenter'` (String) would no longer be honored — no such producer
  exists in `lib/` (checked), and `toJson` never wrote that shape.
- None of the files are generated (`generator_config.dart` header comment
  says "Generated by zfa - Refactored modular version" but it is a
  committed, hand-maintained source file under `lib/src/models/`, edited by
  prior bug fixes; not `.zorphy.dart` output).
