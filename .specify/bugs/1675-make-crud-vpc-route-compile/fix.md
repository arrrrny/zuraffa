# Bug Fix: `zfa make` crud+vpc+route output compiles — published CachePolicy API, typed path params, gate attribution

- **Slug**: 1675-make-crud-vpc-route-compile
- **Fixed**: 2026-09-18
- **Assessment**: ./assessment.md
- **Status**: applied
- **TDD artifacts**: ./tdd/test-list.md, ./tdd/verification.md (this directory)

## Summary

`zfa make <E> --preset=crud --vpc --route` now emits compiling Dart:
(1) the cache-aware repository delete body calls the `CachePolicy.invalidate`
API the published package actually declares instead of the nonexistent
`markStale`; (2) the route plugin's `zfa make` path forwards the entity's
resolved id field type into the route builder, so path parameters are parsed
per the bound field type (`int.parse(state.pathParameters['id']!)` for
`id:int`) instead of assigning a raw String into the typed view field;
(3) `zfa build`'s analyze gate attributes files `zfa make` just wrote to
generator output instead of labeling them "hand-authored offending (not
generator output)". The full repro compiles through the analyze gate with
zero hand-patching.

## Review-fix follow-up (review of `16682a3`)

The automated review of this PR's head raised one 🟡 finding and one 🔵
no-change-requested note; the per-thread verdicts and reasons are posted as
a comment on the PR. Only the 🟡 finding produced code changes here.

- **🟡 `build_command.dart:891-895` — over-attribution window** (applied).
  The make-owned segment test matched `/data/`, `/domain/`, … anywhere in
  the analyzer path although the doc comment above it claimed "under the
  output dir", so hand-authored code in `test/data/…` or `lib/data/…` was
  attributed to the generator — the #1675 misdirection, inverted. The test
  is now anchored to the resolved output dir and matches at the path start
  or under a leading `./`/project dir (how `dart analyze` prints
  project-relative paths). `analyzeGateRemedyLines` gained an `outputDir`
  parameter defaulting to `GeneratorConfig.fixedOutputDir` (`lib/src`), so
  the anchor is explicit and testable rather than implicit; `zfa build` has
  no output-dir flag, so the default is the call site's real value. The
  residual case — hand-authored code inside an owned segment *under* the
  output dir — cannot be told from make output by path alone; that the
  intended semantics there is "generator output" is now stated in the
  classifier's doc comment and pinned by
  `test/commands/build_command_generated_path_attribution_test.dart`
  (the pin the finding asked for, in the default fast lane; the two
  pre-existing classifier suites are `slow`/`regression`-tagged and never
  run there).
- **🔵 `route_plugin.dart:262-265` — `int.parse` on a malformed URL id**
  (skipped: no change requested). The finding is explicitly a follow-up
  note and the throwing parse shape is the pre-existing #336 contract this
  PR pins; it needs a dedicated issue (`int.tryParse` + an error/redirect
  builder for the typed cases).
- **Out of scope (review body, "unverified end-to-end")**:
  `route_builder.dart:1139` hardcodes the path-param key / view arg name
  `'id'` regardless of `config.idField`, so a custom `--id-field` name on
  the make path may still mis-wire the route→view arg. Untouched here; it
  needs its own issue with a repro.
