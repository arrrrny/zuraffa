## Body

## Context

Smoke-testing zuraffa v6 (goal: any agent builds a ZikZak-class app with ONLY zfa commands). Used the new `zfa app shell` generator (#363) on a fully zfa-generated app (`apps/zikzak_demo`). The generated `lib/main.dart` does not compile — it calls `setupDependencies()` with no arguments, but the generated DI `setupDependencies` requires a `GetIt` argument.

## What I ran

```bash
zfa app shell --title "ZikZak Demo" --force   # on an app with full DI generated via zfa make --with=di
zfa build
flutter analyze
```

## Expected

Generated `main.dart` compiles against the generated DI.

## Actual

```
error • This expression has a type of 'void' so its value can't be used ... lib/main.dart:7:9   (use_of_void_result)
error • 1 positional argument expected by 'setupDependencies', but 0 found ... lib/main.dart:7:27  (not_enough_positional_arguments)
```

Generated `lib/main.dart`:

```dart
// Generated by zfa
import 'package:flutter/widgets.dart';
import 'package:zikzak_demo/src/app/my_app.dart';
import 'package:zikzak_demo/src/di/index.dart';

void main() async {
  await setupDependencies();          // <-- no-arg call
  runApp(const MyApp());
}
```

Generated DI (`lib/src/di/index.dart`):

```dart
void setupDependencies(GetIt getIt) {   // <-- requires GetIt
  registerAllUseCases(getIt);
  ...
}
```

## Root cause

`lib/src/commands/app_shell_command.dart` hardcodes the no-arg call (`// lib/main.dart — void main() → await setupDependencies() → runApp(const MyApp())`, doc at line 17), but the DI plugin's `registration_builder.dart:49` emits `setupDependencies(GetIt getIt)`. The two generators disagree on the DI entrypoint signature. The shell command's pre-flight check (`app_shell_command.dart:135`) only verifies that `di/index.dart` *contains* `setupDependencies` — it does not check the call signature.

## Suggested fix

1. Align on ONE signature. Options:
   - Make DI emit a no-arg `setupDependencies()` that internally uses `GetIt.instance` (cleanest for the shell's `await setupDependencies()`), OR
   - Make the app-shell generator emit `await setupDependencies(GetIt.instance);` (import `package:zuraffa/zuraffa.dart` for `GetIt`).
2. Harden the shell's pre-flight check to verify the actual signature (parse the emitted `setupDependencies` declaration) so the mismatch fails loudly at generation time, not at analyze time.
3. Add a regression test: run `zfa app shell` on a project with `zfa make`-generated DI and assert `main.dart` compiles (the existing shell regression tests apparently don't cover the real DI signature).

## Impact

The new `zfa app shell` (#363) — a headline fix for the zfa-only workflow — produces a non-compiling `main.dart` on any app whose DI was generated by `zfa make --with=di` (the canonical flow). Blocks the app shell feature and the whole zfa-only end-to-end path.
