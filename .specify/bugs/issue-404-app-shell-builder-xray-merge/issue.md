## Summary
`zfa` cannot be built from current `development` (HEAD f793e17). `dart build cli --target=bin/zfa.dart` fails to compile `lib/src/plugins/app_shell/builders/app_shell_builder.dart`.

## Command run
```bash
bash scripts/rebuild.sh
# -> dart build cli --target=bin/zfa.dart -o build/zfa_bundle
```

## Expected
`zfa` binary compiles and installs to ~/.local/bin/zfa.

## Root cause
`AppShellBuilder.buildMain` (lines 81-217) is in a broken merged state:
1. It references `xray` (lines 106, 173, 190) but `buildMain`'s parameter list (lines 82-87) has no `xray` parameter.
2. It references `library` (line 184) but never declares a `library` local within `buildMain` -- `buildMyApp` (line 294) and `buildAppRouter` (line 324) each declare their own `library`, but `buildMain` does not.
3. `leading` is declared twice: the mockHint version at lines 162-164 (`final leading = mockHint ? ... : '// Generated by zfa';`) and the xray-aware version at lines 166-181 (`final leadingParts = ...; final leading = leadingParts.join('\n');`).

This looks like a bad merge between the X-Ray feature (#367) and the leading/mockHint change. Likely introduced around `b955d75 fix(app-shell): restore xray param + buildXRayDecksBarrel to unblock dev CI`.

## Impact
`zfa` cannot be built from `development`. Blocks all downstream smoke tests (e.g. the zikzak_demo clone built only with zfa commands).

## Suggested fix
In `buildMain`:
- Add `bool xray = false` to the parameter list (threaded from the `app shell` command).
- Declare a `library` local from the `specs` (mirror `buildMyApp`/`buildAppRouter`).
- Consolidate the two `leading` declarations into a single leading-comment computation that accounts for both `mockHint` and `xray`.

## Environment
