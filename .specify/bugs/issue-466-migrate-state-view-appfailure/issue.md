## Body

## Summary
`zfa migrate state` (zfa v6.0.0) generates `*_view_state.dart` files that reference `AppFailure` but do not import it, producing **non-compiling generated code**. This violates the v6 "no non-compiling generated output" contract and stops any CLI-driven v6 migration of real apps.

## Reproduction
Environment:
- zfa v6.0.0
- Flutter 3.47.1 (stable), Dart 3.13.1
- Repo: arrrrny/zik_zak, branch development (142 entity dirs, 34 mixed v5 state classes)

Steps:
```bash
cd <zik_zak>
zfa migrate state
flutter analyze
```

## Expected
`zfa migrate state` exits 0 and the generated `*_view_state.dart` files compile. The sibling `*_domain_state.dart` files already correctly emit `import 'package:zuraffa/zuraffa.dart';`.

## Actual
- `zfa migrate state` exits 0 ("Migration complete"), creating 68 files / modifying 34.
- `flutter analyze` reports **99 `undefined_class` errors** for `AppFailure` across **33** generated `*_view_state.dart` files.

Example:
```
error • Undefined class 'AppFailure'. ...
  • lib/src/presentation/pages/app_config/app_config_view_state.dart:7:3 • undefined_class
error • Undefined class 'AppFailure'. ...
  • lib/src/presentation/pages/app_config/app_config_view_state.dart:11:3 • undefined_class
error • Undefined class 'AppFailure'. ...
  • lib/src/presentation/pages/app_config/app_config_view_state.dart:15:13 • undefined_class
```

Generated file (`app_config_view_state.dart`):
```dart
// GENERATED by 'zfa migrate state' -- review and adjust as needed.
import 'package:flutter/material.dart';

class AppConfigViewState extends ChangeNotifier {
  AppFailure? _error = null;   // AppFailure not imported
  ...
}
```

## Root cause
The `migrate state` view-state template emits the `AppFailure` type (for the `error` slice) but only emits `import 'package:flutter/material.dart';`. It is missing the import for `AppFailure`. `AppFailure` is `sealed class AppFailure` at `lib/src/core/failure.dart`, exported by `package:zuraffa/zuraffa.dart` (zuraffa.dart:137 `export 'src/core/failure.dart';`). The `*_domain_state.dart` template already imports that package; the `*_view_state.dart` template does not.

## Suggested fix
Add `import 'package:zuraffa/zuraffa.dart';` to the `*_view_state.dart` template, matching the import already emitted for `*_domain_state.dart`.
