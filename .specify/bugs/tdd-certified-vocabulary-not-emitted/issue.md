# Issue: tdd/app-shell — certified skin vocabulary (zuraffa_ui / ZuraffaApp) is never emitted or required by the CLI

- **Issue**: #1260
- **Severity**: high
- **Lane**: tdd/app-shell
- **Status**: open (remediation in progress)

## Summary

`zuraffa_ui` positions itself as **the skin lane's certified vocabulary**
(identified `Zfa*` components + `ZfaTheme`/`ZfaThemeData` + the contract kit)
and `ZuraffaApp` as **the certified app shell of the skin lane** (route
observer + audit bus + violation chrome + `Zfa*` components mounted in one
place). But the `zfa` CLI cannot produce an app that uses either.

## Root cause

1. `zfa tdd init` does not add the `zuraffa_ui` dependency (only the testing
   `dev_dependencies`).
2. `zfa tdd gen --kind widget` boots the generated widget test in a raw
   `ShadApp` (or `MaterialApp` via `--widget-shell materialapp`) — there is no
   `zuraffaapp` shell option, so skin tests never exercise the certified shell
   the real app will run under (no `ZuraffaRouteObserver`, no `ZfaAuditBus`,
   no violation chrome).
3. `zfa app shell` emits `MyApp` + `MaterialApp.router` — not `ZuraffaApp`.
4. `grep -r zuraffa_ui lib/src` in the CLI source: zero hits. The certified
   vocabulary is entirely unreachable from the toolchain.

## Impact

Every skin-lane project generated by the toolchain ships tests and app
shells that bypass the certified contract infrastructure. The certified
vocabulary is dead weight: consumers must hand-assemble what the CLI was
built to guarantee.
