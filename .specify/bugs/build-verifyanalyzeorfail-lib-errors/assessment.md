## Symptom

The regression test asserts that running `dart analyze lib` over the real package yields no errors (`verifyAnalyzeOrFail` returns `true`). It returns `false` because `lib/src/api/bridges/product_api_bridge.dart` fails to compile — its two imported source files do not exist, leaving `GetProductUseCase` and `Product` undefined. The test's premise ("the current lib is warning/info-only") is false: `lib` genuinely contains 2 analysis errors.

4. Run `dart test test/commands/build_command_unit_test.dart -n 'verifyAnalyzeOrFail'`; the test at line 589 fails with `Expected: true, Actual: <false>`.

## Root Cause Hypothesis

The committed, generated file `lib/src/api/bridges/product_api_bridge.dart` (header: `// GENERATED BY \`zfa api Product\` — DO NOT EDIT BY HAND`) is an **orphaned generated artifact**. It imports a `Product` entity (`lib/src/domain/entities/product/product.dart`) and use case (`lib/src/domain/usecases/product/get_product_usecase.dart`) that were never generated/committed into this repo — there is no `lib/src/domain/entities/` or `lib/src/domain/usecases/` directory whatsoever. With both import targets missing, the analyzer reports `uri_does_not_exist` plus `non_type_as_type_argument`/`undefined_class` for `GetProductUseCase` and `Product`. `lib` therefore does not compile, so `verifyAnalyzeOrFail` returns `false` and the regression test fails. Confidence: **high** — confirmed by `dart analyze lib/src/api/bridges/` producing exactly these 4 errors and by verifying the imported paths and the whole `domain` layout.

Note: this is **not** a bug in `verifyAnalyzeOrFail` (the unit under test) — that code behaves correctly. The test is a legitimate canary that has surfaced a real broken `lib/`.

## Proposed Remediation

**Preferred**: Remove the orphaned generated bridge if the `Product` API feature is not part of this repo's intended surface:
- Delete `lib/src/api/bridges/product_api_bridge.dart`.
- Optionally clean up the stale doc comment at `lib/src/core/api_bridge.dart:43`.
This restores a clean `dart analyze lib` and the test passes (the remaining ~15 issues are warnings/infos, which `analyzeReportsError` intentionally ignores).

**Alternatives**:
- If `Product` is meant to be a real feature, regenerate it via the canonical v5 workflow: `zfa entity create Product` → `zfa make Product --preset=crud ...` → `zfa api Product` → `zfa build`, so the entity + use case files exist and the bridge's imports resolve. (Per AGENTS.md STOP-ON-ROADBLOCK, agents driving `zfa` must stop on any generation gap; this assessment only recommends the path, it does not execute it.)
- Do **not** weaken the test (e.g., dropping the whole-package `dart analyze` or asserting `false`). The test correctly detects lib errors; masking it would hide the real breakage.

**Files likely to change** (fix phase only — this assessment modifies none):

- `lib/src/core/api_bridge.dart:43` (optional doc cleanup)
