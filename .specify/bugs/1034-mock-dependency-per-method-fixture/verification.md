## Verdict paragraph

The branch fixes the dependency-mode mock provider template (#1034): it
hardcoded the canned expression to `<T>MockData.sample<T>` (the #1030
single-fixture shape), so `zfa mock` service-mode providers returned the same
canned fixture for every call even when the target entity's mock data class
declared a deterministic per-method selector (`static User forMethod(...)`)
and the params entity carried the discriminator field that selector switches
on. The fix adds content-derived detection in `MockProviderBuilder`
(`_forMethodSelectorParamType` reads the generated mock-data file;
`_discriminatorField` matches the selector's parameter type against the
params entity's analyzed fields) and threads
`<T>MockData.forMethod(params.<field>)` in BOTH emission sites (the
interface-conformance branch and the default service-method branch, each in
its Future and Stream shapes). Detection is derived only from files on disk —
same project state ⇒ same generated bytes, preserving the data-model
determinism invariant. Mock data generation itself is untouched: when no
selector or no matching discriminator exists, the emitted provider is exactly
the pre-fix single-fixture shape (#1030 invariant), and that fallback is
pinned by dedicated guard tests, not by hope.
